Local Router Studio - מפת דרך ל-1.0 Beta

מסמך חי למוצר עצמאי ופשוט: המשתמש מדליק תוכנה אחת, מקבל מודל חזק מקומי, רשת תתי-סוכנים, דשבורד ויזואלי, ותוצרים בלי לראות קוד.

סטטוס: חי ומתעדכן עודכן: 2026-06-18 כיוון מאושר: Native Router Studio עיקרון: Ponytail - מינימום שעובד

החלטת מוצר

1.0 Beta יהיה מוצר עצמאי: Local Router Studio. לא "תוסף ל-Agent Zero", לא "LangFlow clone", ולא מערכת שמבקשת מהמשתמש להבין Docker, llama.cpp, YAML או קוד.

LangGraph ו-LangFlow נשארים רעיונות להמשך. בגרסת הבטא נבנה flow ויזואלי פשוט משלנו מעל מצב שכבר קיים ב-SQLite ובדשבורד.

יעד בטא

  • התקנה/הפעלה אחת.
  • בחירת מודל אוטומטית או מומלצת.
  • משימה אחת נכנסת, רשת סוכנים יוצאת לעבוד.
  • דשבורד מציג התקדמות ותוצרים.
  • אין prompt bodies בטלמטריה.

מה כבר קיים במוצר

  • OpenAI-compatible router: /v1/models, /v1/chat/completions.
  • Routing מוסבר: aliases, auto, strategies, analytics.
  • Dashboard קיים: Overview, Connect, Compare/Routing, Orchestration, Cookbook.
  • Cookbook סורק GGUF ומחשב התאמה ל-VRAM.
  • Fleet control קיים אך כבוי כברירת מחדל.
  • Orchestrator: plans, tickets, instances, personas, DOX, WAKE.
  • בדיקות hermetic רחבות.

מה עדיין חסר לבטא אמיתית

  • Onboarding שמסתיר קבצי config.
  • Runner מינימלי שמריץ תתי-סוכנים בפועל.
  • Model setup בטוח: לא להוריד עשרות GB בלי אישור מפורש.
  • Readiness UX: מה קריטי, מה אופציונלי, ומה לתקן עכשיו.
  • Release/versioning: הגרסה בקוד, README והדשבורד חייבים להיות מסונכרנים.
  • Browser smoke לדשבורד, מעבר ל-string tests.

שלבי פיתוח עד 1.0 Beta

0.3.1

ייצוב אחרי ה-merge האחרון

מטרת השלב: להפוך את main הנוכחי לבסיס נקי.

  • לסנכרן version: __version__, README, dashboard.
  • לשפר doctor: critical / optional / disabled slots.
  • לעדכן docs מיושנים, במיוחד runbooks שמזכירים קבצים שכבר לא קיימים.
  • להוסיף בדיקת dashboard smoke בסיסית.
0.4.0

Onboarding ללא קבצי config

המשתמש לא אמור לערוך YAML כדי להתחיל.

  • מסך Setup בדשבורד: חומרה, תיקיית מודלים, slots, API key.
  • Auto-detect ל-GGUF folder ו-llama.cpp server קיים.
  • יצירת config מקומי מתוך UI, עם preview לפני שמירה.
  • כפתור "Run readiness check" שמסביר בעיות בעברית/אנגלית פשוטה.
0.5.0

Model autopilot

בחירה אוטומטית של מודל חזק ותתי-מודלים לפי החומרה.

  • Cookbook הופך ממסך המלצות למסך "Apply recommendation".
  • חלוקת roles: planner, worker, scribe/reviewer, embed אם קיים.
  • אם אין מודל מתאים: להציע רשימת אפשרויות, לא להוריד אוטומטית.
  • לשמור החלטות כ-profile מקומי שניתן לשחזר.
0.6.0

Runner מינימלי לתתי-סוכנים

זה השלב שבו orchestration מפסיק להיות observe-only בלבד.

  • Local runner ראשון: Python subprocess או task loop פנימי, לא Docker כברירת מחדל.
  • Bounded concurrency לפי חומרה: כמה workers רצים במקביל.
  • כל worker מקבל persona + DOX + ticket prompt + artifact folder.
  • ה-runner מדווח דרך /orchestrator/instances/{id}.
  • Stop/cancel task בסיסי.
0.7.0

חוויה ויזואלית של העבודה

לא LangFlow עדיין. תצוגה פשוטה שמסבירה מה קורה.

  • Flow view: Planner -> Tickets -> Workers -> Review -> Result.
  • Timeline לאירועים: created, running, blocked, completed.
  • Artifact browser לתוצרים.
  • התראות ברורות: blocked, failed, model unavailable, no capacity.
0.8.0

Task UX למשתמש לא טכני

המסך הראשי צריך להיות "מה תרצה להשיג?", לא "בחר endpoint".

  • Task composer פשוט עם goal, files/context, output type.
  • Templates: research, coding, docs, planning, local files.
  • Preview של plan לפני הרצה.
  • תצוגת privacy: מה נשאר מקומי ומה נשלח למודל.

1.0.0-beta

בטא ציבורית

קריטריון: משתמש לא טכני יחסית יכול להפעיל, להריץ משימה, לראות סוכנים, ולקבל תוצר.

  • אפליקציה נפתחת לדשבורד, לא לטרמינל בלבד.
  • Setup guided עובד ללא עריכת YAML ידנית.
  • מודל חזק נבחר או מומלץ באופן ברור.
  • רשת תתי-סוכנים רצה במגבלת משאבים.
  • תוצרי העבודה נשמרים וניתנים לפתיחה מהדשבורד.

לא לבטא

  • LangFlow canvas מלא.
  • Docker orchestration כברירת מחדל.
  • Cloud BYOK.
  • Marketplace של agents.
  • Fine-tuning או model training.

שיקול: LangGraph

מתאים אם ה-flow הפנימי נהיה מורכב מדי ל-SQLite state machine פשוט. לא להכניס לפני שיש runner עובד ו-3 workflows שחוזרים על עצמם.

Gate: להוסיף רק אם הוא מוחק קוד משלנו, לא אם הוא מוסיף שכבה.

שיקול: LangFlow

מתאים למשתמשים מתקדמים שרוצים לערוך workflows. למשתמש הממוצע זה עלול להיות יותר מדי. עדיף להתחיל עם flow view לקריאה בלבד.

Gate: להוסיף אחרי שיש דרישה לעריכה ויזואלית, לא רק צפייה.

בטיחות אין prompt bodies בטלמטריה, public bind דורש auth. Hermetic tests + config preview checks.
שחרור version, docs, changelog, README מסונכרנים. Release checklist.
