# llama.cpp v1.0.0 runtime pin

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the managed Windows CUDA runtime from the pinned nightly `b12110` to nightly `b12359`, the binary build named by the llama.cpp `v1.0.0` release, without adopting new server flags in the same change.

**Architecture:** `v1.0.0` is a source release. Its GitHub assets are only `nightly-tag.txt`; the Windows zips live on `b12359`. The installer already accepts a `b<digits>` tag and rewrites the `b9987` asset template in `runtime_catalog.json`. Keep that template on CUDA 12.4. Teach the `v*` rejection to name the rolling id, lock the argv Imperium already sends, then smoke `b12359` before changing the recommended catalog pin.

**Tech Stack:** Python setup engine, subprocess/docker llama-server argv, pytest, managed runtime under `%LOCALAPPDATA%\Imperium\runtime\llama.cpp\versions`.

**Spec:** this file. Upstream notes: https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0 (published 2026-11-13, `target_commitish` `2d8a32502909ca065c41c4cf5f2fb1c427c047fc`, nightly **b12359**).

## Global Constraints

- Install target is `b12359` with the existing `cuda12` assets `llama-b12359-bin-win-cuda-12.4-x64.zip` and `cudart-llama-bin-win-cuda-12.4-x64.zip`.
- `imperium update` without `--tag` walks `releases?per_page=20`. On 2026-11-16 that window is `b12414`–`b12436`, so an unpinned update does not land on `b12359`.
- Tag `v1.0.0` stays rejected. It has no Windows zip.
- CUDA 13.5 assets exist and are out of scope. Driver floor stays the catalog's CUDA 12.4 floor (`min_driver` `551.61`).
- First move keeps the current argv. New opt-in flags stay off.
- Loopback bind stays `127.0.0.1`. No `--allow-unauthenticated-tools`. No `--media-allow-private-urls`.
- Do not send `--defrag-thold`. v1.0.0 removed it.
- Hermes swap stays process replacement (ADR 0015). Do not switch the slot to llama.cpp router mode.
- No new advanced-flag UI (ADR 0003).
- Live machine before this work: runtime `b12110` channel `pinned`, previous `b10686`.

## Review Focus

- An unpinned `imperium update` installs a nightly newer than `b12359`. Expect `update` with no `--tag` to be refused by the operator procedure below.
- `imperium update --tag v1.0.0` must fail before any download, and the error must name `b12359`.
- `--fit on` now accounts for skipped NextN layers, so the same GGUF can come up with a different `n_gpu_layers`. After the smoke, `effective_n_ctx` comes from `/props` or stays `Unknown` (ADR 0015). A missing probe is not a successful context claim.
- MTP is still `--spec-type draft-mtp`. A failed first start must still retry the same GGUF without speculative flags. The watcher already does this; the smoke must show a clean MTP start or that bounded retry, and must not leave the slot answering from the previous model.
- Turning vision on later without `--media-allow-private-urls` rejects private `image_url` values. This move does not enable vision. The command-contract test fails if that flag appears.

## What stays out

FP8 KV (`-ctk/-ctv f8_e4m3`), `--moe-cache-mib`, `--moe-cache-cpu-share`, `--shard`/`--ple`, and `/v1/audio/speech` are follow-ups. They need a measured profile change after `b12359` is the running runtime. `context_planner.KV_BYTES` has no `f8_e4m3` entry; do not add one in this plan.
